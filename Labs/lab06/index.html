Labs 1 & 2

Published on September 18, 2026 by Rosh Talla Defo

In Labs 1 and 2, I learned how to set up GitHub to create a webpage that is both manageable before publication and version-controlled for updates and pushing it to the web. I also learned how to properly write HTML code with good semantic structure and elements that enable good design. The biggest thing about hand-coding is that it makes you slow down and think about the sequencing of where things go and why, and what dependencies help you make sense of what the hypertext is doing for the front-end interface. Whenever I got stuck, I would go back to the linked lessons on MDN or review example code to check whether my structure matched, and for Module 1 I reviewed the setup video again to make sure I had followed every step of creating my GitHub account.

What I Learned

  1. How to set up GitHub for version control and to publish a webpage
  2. How to write HTML with proper semantic structure and elements
  3. How hand-coding forces you to slow down and understand the sequencing and dependencies behind a page's structure

Learning CSS

Published on October 4, 2026 by Rosh Talla Defo

One thing this assignment taught me is that structure alone is not enough to communicate information effectively on a website. CSS can bring alive a custom and curated system of thought and create a navigation experience that reinforces navigational rules and standards and creates patterns for users to familiarize themselves with. I found a challenge to be the classification of selector application, and knowing what can best communicate information as a system expands, since on a huge webpage it can get overwhelming. My approach was taking notes to understand the usage of descendant selectors, classes, IDs, and CSS rule formatting as a system scales and as it pertains to bigger web projects. Taking notes helped me uncover the differences between the key concepts and better understand their applications and use cases, like deciding between inline and internal CSS based on the desired outcome.

Best Web Design Practices

Published on November 1, 2026 by Rosh Talla Defo

For Lab 05 I evaluated the Real Madrid website at realmadrid.com/en-US, and I was surprised by what I found. I ran it through an Accessibility Checker and it only scored 10 out of 100, which seems low for a club that size with the resources they have. A lot of the problems came down to things that are not hard to fix, like images without descriptive alt text and text that does not have strong enough color contrast against its background. It made me realize that a site can look polished and still be difficult to use for someone relying on a screen reader, or for someone who has trouble reading low-contrast text. Looking good and being usable are two different goals, and the second one is the easier one to forget.

This lab also introduced me to the CRAP design principles, which stand for Contrast, Repetition, Alignment, and Proximity, and to the idea that a hierarchical site organization helps people find what they are looking for. Repetition stood out to me because it explains why a consistent navigation bar on every page makes a whole site feel easier to use. The two practices I most want to carry into my own pages are writing descriptive alt text for every image and making sure link text says where the link actually goes instead of showing a raw URL. A link that reads "MDN Web Docs: Creating the Content" tells you something, while a link that just prints a long address tells you nothing. I had already started doing both in my earlier labs, and now I understand why they matter instead of just following a rule.
